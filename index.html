AI-Assisted Pricing

Student and Wholesaler dashboards have an “AI Suggest” button. It calculates a fair price using subject, condition and stock (for wholesalers).

Coupons & Rentals

Student has a coupon helper widget and a late-fee calculator. General users have rental tools only. This matches the role difference in your PPT.

Shared Data Model

All pages use a single array stored in localStorage["libro_all_listings"]. This mocks how a real backend database would work.

Live Search & Filters

All role dashboards offer instant search by title or subject in their own listings, making the UI more realistic and usable.

Analytics & Exports

Wholesalers see total SKUs, stock and potential revenue, plus a mini subject bar chart and CSV export option — perfect for explaining “reports” part of the PPT.

Role-Based Access

Each dashboard checks currentUser.role. If someone opens a page directly with the wrong role, an Access Denied message is shown.

Demo flow you can explain.

During your presentation, you can literally point to these four steps and show how the application flows from login to admin approval.

  1. 1

    User selects their role on login.html.

    Student / General / Wholesaler is saved in localStorage as currentUser. They are then redirected to the correct dashboard page.

  2. 2

    Dashboard validates if the user is allowed.

    Each page checks for both authToken and the correct role. If anything is wrong, it shows an Access Denied card instead of the dashboard.

  3. 3

    User creates a book listing.

    Student / General / Wholesaler forms push a new object into libro_all_listings with status pending. This listing appears in their respective “My Listings” / “Inventory” section.

  4. 4

    Admin updates approval status.

    On admin.html, the admin updates each listing to approved or rejected. When any role refreshes their page, the colored badge reflects the latest status.

Next step after this project?
